VESPER / VESPER FETCH DATA

把研究的起点，放回数据里。Research starts with the data.

回测之前，先把每天要用的数据整理好。这条流水线从指数成分股出发，把分红送转、历史行情与交易时段的数据接在一起，让下游研究有一个可以反复回来的起点。Before a backtest comes the less visible work of preparing the data. This pipeline starts with index constituents and connects corporate actions, historical prices and trading-session updates into a shared research input.

机制流程Mechanism功能组成Capabilities流程与界面设计Design study研究边界Scope
01

历史数据维护Historical data

维护沪深 300、中证 A500、科创 50、创业板 50 等指数成分股及 canonical 前复权行情。Maintain constituents and canonical adjusted prices for index universes including HS300, A500, KC50 and CY50.

02

分红与实时融合Corporate actions and live fusion

根据分红除权日期处理受影响的历史数据，并在读取、导出和交易时段融合补充数据。Handle history affected by corporate-action dates and combine supplemental data at read, export and intraday stages.

03

存储与交付Storage and delivery

使用 Parquet 组织数据，按北京时间调度任务，并保留导出与通知流程。fetch_data2duck 探索 DuckDB / Parquet 存储，xls2db 是配套表格转换脚本。Organize data in Parquet, schedule by Beijing time and support export and notification workflows. fetch_data2duck explores DuckDB/Parquet storage; xls2db supplies a spreadsheet conversion utility.

DESIGN NOTES / 设计推演DESIGN STUDY

先看覆盖，再看任务。Coverage first, tasks second.

从现有项目的功能出发，梳理操作顺序与信息层次。以下界面是为介绍项目绘制的设计示意，不是运行截图。These design studies organize the existing project’s capabilities into a workflow and information hierarchy. The interface below is an illustrative concept, not a running application screenshot.

  1. 01

    先理清来源Map the sources

    把成分股、分红与行情分开看，明确它们在哪一步汇合。Separate constituents, corporate actions and prices, then identify where they meet.

  2. 02

    再标出依赖Expose dependencies

    让复权维护、历史补齐和实时融合有清楚的前后关系。Make dependencies between adjustment maintenance, backfill and live fusion explicit.

  3. 03

    最后留出复核Leave room for review

    把任务状态、日志与导出放在同一工作路径里，方便定位问题。Keep task state, logs and exports close enough to investigate problems.

总览与操作分开Separate overview and action

先回答数据在哪里、覆盖到哪，再进入具体更新任务。Establish location and coverage before opening an update task.

状态贴近任务Keep status beside the task

任务详情里放执行阶段和日志，不让用户在几个页面之间猜进度。Put stage and logs in task details rather than making the user infer progress across pages.

研究边界Research scope

这是数据工程项目。数据完整性、复权一致性和来源可用性仍需检查；流水线输出不等于经过验证的交易信号。This is a data engineering project. Completeness, adjustment consistency and source availability still need checking; pipeline output is not a validated trading signal.
